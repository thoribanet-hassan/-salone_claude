# خارطة التحسينات المقترحة — دورك

> مصدرها: مستشار المستخدم (2026-06-16). **لا تُنفَّذ الآن** — مرجع للجلسات القادمة.
> لكل بند: تقييم كلود + ربطه بما هو **مبني فعلاً** (تجنّباً لإعادة بناء موجود).
> الفلسفة المتّفق عليها: **لا ذكاء اصطناعي الآن** — استقرار + إشعارات + تجربة QR + سهولة تفعيل + جمع بيانات تشغيل حقيقية أولاً.

---

## ما هو مبنيٌّ أصلاً (مهم قبل البدء)

- **لوحة المؤسس `/founder`**: إجمالي المنشآت، النشطة اليوم/٧أيام، مسحات QR، فتح صفحة الانتظار، تذاكر يوم/٧أيام/إجمالي، متوسط التقييم، نسبة التحويل + قمع الزوّار الفريدين، جدول المصادر، توزيع أنماط الزمن، أعلى ١٠ منشآت، **منشآت لم تُستخدم** + **خاملة ≥٧أيام**، الاشتراكات، إعادة تعيين كلمة المرور.
- **إحصاءات المدير `/dashboard/stats`**: لكل موظف عدد المكتمل + الإيراد (يومي/شهري) + تفصيل الأيام.
- **جدول `events`** (المصدر الذهبي لكل التحليلات): QR_SCANNED، WAIT_PAGE_OPENED/REVISITED، TICKET_CREATED/CANCELLED/CALLED، SERVICE_STARTED/COMPLETED (meta.serviceMinutes)، NO_SHOW، APPOINTMENT_CREATED، SERVICE_RATED — مع `visitorId` (كوكي `dwk_vid`) و`source`.
- **إعلانات المنشأة الذاتية** (`ownerShopId`): نص + صورة/فيديو + موضع — أساس البند ٩.
- **شاشة الموظف `/serve`** + شاشة العرض `/display` (قسم «حان دوركم» الوامض).

**خلاصة:** أجزاء كبيرة من البنود ٣ و١٠ (والجزء العلوي من ١ و٦) موجودة بالفعل؛ العمل الجديد أصغر مما تبدو القائمة.

## ملاحظة جمع البيانات (افعلها مبكراً ولو لم تُبنَ اللوحات بعد)

جودة التحليلات لاحقاً تعتمد على التقاط الحقول من الآن:
- **مدينة المنشأة** عند التسجيل (لبند ١٠ «أكثر المدن» — حقل واحد رخيص).
- **شعار المنشأة** (لبند ٢ ولهوية الشاشات).
- (معدّل العودة وأكثر الخدمات والقمع: حقولها موجودة في `events`/`tickets`.)

> القاعدة: لا تُسقِط حدثاً قابلاً للالتقاط الآن لأن لوحته ستُبنى لاحقاً.

## ترتيب التنفيذ المقترح من كلود (عند البدء)

1. **#2 درجة التفعيل + #1 لوحة صحة المنشأة** — أعلى رافعة لمشكلة «سجّل ولم يستخدم» (وهي خطرك الأول الآن، ولوحة المؤسس تحصيها فعلاً).
2. **#8 تحسين قمع أول عميل** — يرفع نسبة التحويل التي تُقاس أصلاً.
3. **#3 تنبيهات الخمول الاستباقية** (تكملة بسيطة لما في `/founder`).
4. **#6 + #7** — مؤشرات شهرية ثم توصيات بقواعد فوقها.
5. **#10** — سدّ ثغرات لوحة المؤسس (مدن/خدمات/متوسط انتظار).
6. **#4 + #9** — تحسينات UX/إعلانات عند توفّر الوقت.
7. **#5 الفروع** — مؤجّل حتى الطلب الفعلي.

## مؤجَّلات تقنية لما بعد التجربة (قرارات مؤكَّدة)

- **استرجاع كلمة المرور الذاتي بالبريد** (2026-06-16): المدير يعيد التعيين بنفسه عبر رابط يصل إيميله. التدفّق: `/forgot` (إدخال البريد) → جدول `password_reset` (توكن مُجزَّأ + انتهاء) → بريد فيه `/reset/<token>` → كلمة جديدة. **المتطلّب الذي أخّره:** خدمة إرسال بريد (موصى: Resend) + تحقّق دومين dawrak.shop بسجلات DNS + مفتاح API في `.env`. حالياً يكفي رابط واتساب «نسيت كلمة المرور» على `/login` (مبني) + إعادة تعيين المؤسس من `/founder`. يُبنى مع تراجع تلقائي للواتساب حين لا يكون البريد مهيّأً.

## الذكاء الاصطناعي — لاحقاً (متّفق عليه)
بعد أشهر من البيانات الحقيقية: تحويل الأرقام لتوصيات، تحليل أسباب التراجع، محادثة مع البيانات، التنبؤ بالازدحام، التسويق الذكي — **كمستشار تشغيل** لا مجرد شات. الأساس (جدول `events`) يجعل هذا ممكناً بلا إعادة هيكلة.
